# PRD 작성 가이드

## 역할

PRD는 PROMPT(대화 로그)에서 도출한 **요구사항 정제본**이다. "무엇을·왜" 를 다룬다.
PROMPT와 **병행 작성**하며(대화가 진행될수록 갱신), `make-plan`에 전달되는 입력 문서다.

## 편집 규칙

- 편집 가능한 정제본이다 (PROMPT와 달리 기존 내용을 고쳐 쓸 수 있다).
- **PRD 본문의 내용 변경은 사용자 발언을 근거로 한다.** 단, 현재 상태·리스크의 사실 설명은 직접 확인한 파일:라인을 근거로도 갱신할 수 있다.
  - 사용자가 말한 내용(자발적 답변이든, 내 질문에 대한 답이든)을 반영하는 것은 **자유롭게** 한다.
    그 발언이 곧 근거이자 승인이며, 별도 승인 절차를 두지 않는다.
  - 발언이 없는데(예: 코드 탐색 중 발견) 요구사항을 바꿔야 하면, **먼저 질문**해 답을 받고 그 답을 근거로 반영한다.
  - 내가 임의로(사용자 발언 없이) 요구사항을 추가·축소·변경하지 않는다.
- 운영 정보(진행 상태·재개 정보·요구사항 ID·체크리스트 표시와 근거 참조)는 확인된 사실과 기존 문서 내용에 따라 갱신한다. 이 갱신을 이유로 요구사항의 의미·범위·조건·예외를 추가·축소·변경하지 않는다.

## 요구사항 추적

- 목표 상태·범위·제약·성공 조건에 담긴 개별 요구사항에 `REQ-01` 같은 고유 ID와 근거(최초 요청 또는 PROMPT 질문 ID)를 단다. 같은 요구사항을 다른 절에서 언급할 때는 같은 ID를 참조한다.
- ID 부여는 추적을 위한 표기다. 원래 조건·예외를 유지하며, 문장 분리·통합 과정에서 요구사항을 재해석하지 않는다. 기존 ID를 다른 요구사항에 재사용하지 않는다.
- 기존 문서에 ID가 없으면 명확한 절·항목 참조를 유지할 수 있다. 갱신하는 요구사항부터 내용 변경 없이 ID를 부여하며, 과거 PROMPT는 고치지 않는다.

## 완료 기준 (종료 게이트)

PRD 산출물의 `## 11. 완료 체크리스트` 항목을 모두 근거와 함께 `[x]`로 채우면 다음 단계(SPEC 작성과 상세 코드 탐색)로 진행한다.
PRD 작성 전·중의 사전 탐색은 현재 동작·제약의 사실 확인에 한하며, 요구사항 확정과 변경 예정 설계를 대신하지 않는다.

- 근거는 사용자 발언/PROMPT 위치(현재 상태·리스크는 확인한 파일:라인도 가능) 또는 "해당 없음" 사유를 1줄 단다. 추정으로 `[x]`를 표시하지 않는다.
- 항목별 내용은 섹션 템플릿의 같은 번호 절을 따른다. 산출물에서 체크리스트 항목을 임의로 추가·삭제하지 않는다.

## 섹션 템플릿

```md
# PRD

- before-plan 상태: 진행 중
- 재개 정보: 마지막 완료 단계 / 미답 질문 ID(없으면 없음) / 코드 확인 기준

## 1. 개요
- 무엇을 변경하는가

## 2. 변경 배경
- 왜 이 변경이 필요한가

## 3. 현재 상태
- 현재 어떻게 동작하는가

## 4. 목표 상태
- REQ-01: 변경 후 어떤 상태가 되어야 하는가 — 근거: 최초 요청 또는 PROMPT 질문 ID

## 5. 변경 범위
- In scope: ...
- Out of scope: ...

## 6. 영향 범위 (사용자·기능 관점)
- 어떤 사용자 흐름/기능이 영향받는가  (코드·모듈 영향은 SPEC에서 다룸)

## 7. 제약
- 환경·버전·호환성·금지 사항

## 8. 성공 조건
- 각 요구사항 ID(기존 문서는 명확한 절·항목 참조)별로 어떤 상태가 되면 완료로 보는가 (검증 가능하게)

## 9. 리스크
- 예상되는 위험

## 10. 미해결 이슈
- 남은 질문/결정 대기 (있으면 PRD 미완)

## 11. 완료 체크리스트
> 각 항목에 `[x]/[ ]`와 근거(사용자 발언/PROMPT 위치, 현재 상태·리스크는 파일:라인도 가능) 또는 "해당 없음" 사유를 1줄 단다. 근거 없는 `[x]` 금지.
- [ ] 개요 — 근거:
- [ ] 변경 배경 — 근거:
- [ ] 현재 상태 — 근거:
- [ ] 목표 상태 — 근거:
- [ ] 변경 범위(In/Out scope) — 근거:
- [ ] 영향 범위(사용자·기능) — 근거:
- [ ] 제약 — 근거:
- [ ] 성공 조건(검증 가능) — 근거:
- [ ] 리스크 — 근거:
- [ ] 미해결 이슈 없음(있으면 10절에 명시, PRD 미완) — 근거:
```

## 하지 말 것

- 기술 구현 방법(어떻게)을 PRD에 적지 않는다 → 그것은 SPEC.
- 추측을 확정 요구사항으로 적지 않는다 (모호하면 질문하고 PROMPT에 기록).
